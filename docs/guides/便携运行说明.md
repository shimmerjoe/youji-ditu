# 便携运行与开发

仓库根目录就是完整的项目，克隆到任意位置都能用；所有工具都通过 `tools/project_paths.py` 定位目录，不依赖固定的盘符或路径。

## 安装与预览

在项目根目录运行：

```powershell
npm ci
python -m pip install -r tools/requirements-build.txt
npm run preview
```

然后访问 <http://localhost:8765/>（预览的是 `site/` 目录）。Windows 也可以双击 `scripts/windows/打开首页.bat`，关闭服务器窗口即停止预览。完整搜索、模块脚本和离线缓存需要通过 HTTP 访问。

## 哪些文件可以改

| 想改什么 | 改哪里 |
| --- | --- |
| 城市攻略正文 | `content/城市/*.md` |
| 跨城市总览 | `content/记录.md` |
| 页面样式 / 交互 | `frontend/runtime/travel.css`、`frontend/runtime/travel.js` |
| 全站搜索、省份导航 | `frontend/src/*.ts` |
| 页面结构与组件 | `tools/build_travel_html.py`（模板与渲染器）、`tools/site_icons.py` |
| 图片与授权记录 | `site/assets/photos/`、`site/assets/photo-cache.json`、`site/assets/photo-editorial-decisions.json` |

`site/` 下的 HTML、`site/assets/travel.*`、`search-index.js` 和 `roadtrip-data.js` 都是生成文件，每次构建都会被覆盖，不要手工修改。

## 构建与校验

```powershell
npm run check
npm run stage
```

`check` 依次构建 Vite、生成全站，并运行类型检查、测试和站内链接校验；`stage` 生成可部署的 `dist/`。内容报告位于 `docs/reports/内容与图片体检.md`。

## 提交与发布

先审查 `git status` 和 `git diff`，选择性地暂存和提交，然后推送到 `main`。`scripts/windows/发布更新.bat` 只推送已经提交的内容。源码上传不等于 GitHub Pages 上线：还需要仓库可见性满足要求、在 Pages 设置里选择 GitHub Actions，并且 Actions 部署成功，详见根目录 README 的“开启公开地址”。
