# 游记地图：本地优先旅行知识工作台设计

日期：2026-08-11
状态：已批准执行（用户要求自主连续迭代）

## 目标

把现有 222 城市静态攻略升级为“构建期双栈、运行期纯静态”的旅行知识工作台：核心攻略在 JavaScript 失败时仍可阅读；搜索、筛选、收藏、计划、清单、预算、笔记、导出和离线状态具备应用级反馈；产物继续部署到 GitHub Pages。

## 已验证基线

- 内容源为 `城市/*.md`、`记录.md` 与 `tools/city-page-meta.json`，由 `tools/build_travel_html.py` 生成页面和 PWA 资产。
- 新鲜基线为 222 个城市 Markdown、222 个城市 HTML；74 个 Python 测试、8 个 Node 路书测试和站点校验通过。
- 原青岛页约 690 KB，包含 6,588 个 DOM 元素、216 张图片节点。根因是每页重复完整城市筛选器和完整侧栏目录。
- 现有浏览器审计覆盖 1920×1080、1366×768、390×844、360×800 的首页、青岛、用户中心和自驾路书。
- 首次浏览器失败不是页面超时，而是 Windows 辅助脚本遗留多个共享端口服务器；按 PID 管理服务后四视口审计成功。

## 研究结论

- 抖音、B站、小红书只借鉴搜索、标签、章节、合集、相关内容和“灵感到执行”的信息路径；不复制界面、文案、图片、视频、评论或品牌元素。
- TRIP/TREK 只借鉴“未安排池—分日时间线—预算/状态摘要—导出”的交互骨架，不迁入其后端、认证或完整代码。
- Pagefind、Leaflet、idb 仅作为有量化门槛的候选，不与同类库叠加。
- 本地 Obsidian 没有旅行专属资料；本地视频只可作为私人设计参考。下载的驾驶舱组件许可禁止公开传播，因此其代码、模板、图片和演示素材不得进入公开仓库。

## 架构决策

### 构建期

1. Python：解析 Markdown、标准化城市/来源/图片数据、预渲染 SEO HTML、生成审计和 PWA 元数据。
2. Node + Vite + TypeScript：构建渐进增强模块、按功能拆包、做类型检查和浏览器侧单元测试。
3. `npm run build`：先构建前端模块，再调用 Python 生成全部静态产物，形成唯一正式构建入口。
4. GitHub Actions：在 Linux 上以锁定的 Python/Node 版本重新构建、测试、校验并部署 GitHub Pages。

### 运行期

- 仍为纯 HTML/CSS/JS，无常驻 Python/Node 服务。
- 城市正文、来源和关键决策信息不依赖脚本。
- TypeScript 交互岛按页面能力启动；未出现对应 DOM 时不加载复杂功能。
- 用户数据仍保存在浏览器本机，先建立版本化存储适配层；实际数据规模需要事务时再评估 IndexedDB。

### 搜索

- 先减小现有全站索引与 DOM 重复，保留无依赖搜索。
- 单独基准 Pagefind 的中文召回、首载体积、离线行为和构建时间；只有明确优于现状才替换，不同时引入 Fuse.js。

### 地图

- 当前不引入地图框架。只有获得可维护的坐标、底图归属、配额和隐私策略后，才比较现有高德方案与 Leaflet。
- 没有实时接口时，里程、天气、路况和费用必须明确标注为参考估算。

## 产品结构

1. 发现：统一搜索、条件筛选、主题集合、相关城市与路线集合。
2. 决策：适游时间、天数、交通、住宿区域、预算、预约与风险在正文前形成可扫描摘要。
3. 计划：待安排池、分日时间线、停留/通勤、状态、预算、冲突和提醒。
4. 出发：清单、来源复核、离线状态、打印/Markdown/ICS 导出。
5. 回顾：最近浏览、完成/归档状态和本地旅行笔记。

## 视觉方向

采用“现代旅行图册 + 野外手册”的编辑型界面：暖白纸面、墨色文字、青绿色主色、交通/美食/风险等语义色；以排版、留白、摄影和连续正文建立层级，不使用玻璃拟态、装饰光球或密集统计卡。桌面端提供高效双栏，移动端折叠次要面板并保留单手可达的核心操作。

## 不做事项

- 不改成需要服务器的 Python 动态站或全量 React SPA。
- 不新增账号、支付、订单、广告、预订、评论、关注或无限信息流。
- 不复制社交平台素材，不发布本地视频片段，不使用许可冲突组件。
- 不在没有数据和验证的前提下宣称实时天气、交通、票价或可预约状态。

## 完成门槛

- 统一构建可在干净环境复现，生成结果无未解释漂移。
- Python、Node、站点校验和浏览器关键流程全部通过。
- 四种指定视口无文档级横向溢出、破图、控制台错误或失效按钮。
- 首页、城市、用户中心、计划和路书的关键操作支持保存、刷新恢复与导出。
- GitHub Pages 部署成功且公开地址通过实际访问验证。
