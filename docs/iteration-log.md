## 2026-08-22 升级第 4 轮：来源媒体再发布门禁

**问题：** 来源页的 `og:image` 只证明下载成功，不证明本站有再发布权；当前缓存中 206 个图片命中均没有许可字段，另有 4 个 Wikimedia 文件页被错误输出为远程 `<img>`。

**原因：** 生成器把“可访问 URL”“本地已下载”和“可公开再发布”混成同一个状态，且直接按扩展名渲染 Markdown 中的远程图片地址。

**修改文件：** `tools/build_travel_html.py`、`tools/test_product_contract.py`、全部生成页面。

**实际改动：** 增加 `source_media_has_republication_rights()`；只有同时具备许可与署名/明确授权的缓存媒体才可作为复制图片，其他来源保留为来源链接。移除远程图片直出，来源页仍可通过上下文链接访问；景点条目复用来源图时也执行同一门禁。

**验证结果：** 先观察到回归测试红（4 个远程图片 URL、53 个 `_sources` 引用），修改并重建后测试转绿；生成页面 `_sources` 图片引用为 0，四视口浏览器审计 round-04 的 16 个页面均 HTTP 200、控制台/页面/网络错误为 0。

**遗留风险：** `_sources` 缓存文件仍保留在工作区，尚未删除；正式发布前需按来源和 Git 归属做一次可逆清理，并检查外部视频嵌入策略。

## 2026-08-22 升级第 8 轮：离线导航降级

**问题：** Service Worker 在断网访问未缓存页面时只返回 `Response.error()`，用户可能看到空白错误页，且没有解释已缓存与未缓存的区别。

**原因：** 导航缓存策略只覆盖网络成功或精确缓存命中，没有可读的最后一道降级响应。

**修改文件：** `tools/build_travel_html.py`、`tools/test_pwa_cache.py`、生成的 `sw.js`、`manifest.webmanifest` 相关产物。

**实际改动：** 为导航策略增加版本化 `OFFLINE_FALLBACK`、可读的中文离线响应（503）和 App Shell 回退；脚本/样式仍只返回缓存或网络错误，避免把 HTML 错当 JavaScript/CSS。新增契约覆盖缓存与离线文案。

**验证结果：** `test_pwa_cache` 8 项通过；Playwright 在真实 Chromium 中先激活 Service Worker，断网访问未缓存路径得到可读 App Shell 200；清空缓存后得到明确 503 离线页并保存 `offline-fallback.png`。线上模式无控制台错误。

**遗留风险：** 浏览器首次安装仍需联网下载 App Shell；未缓存的城市页不会凭空离线生成，需用户先访问或依赖明确提示。

## 2026-08-22 升级第 15 轮：公开规范复核

**研究来源：** [MDN Service Worker fetch](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerGlobalScope/fetch_event)、[MDN PWA 缓存](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching)、[MDN Web Share](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)、[MDN Clipboard](https://developer.mozilla.org/en-US/docs/Web/API/Clipboard_API) 和 [GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。

**实际改动：** 将上述边界落实到第 8、13、14 轮的实现与 README，不引入需要后端或付费服务的新依赖。

**验证结果：** 本地 Chromium 的 HTTP 黑盒测试覆盖离线 App Shell、显式离线页、便携分享链接和隔离上下文恢复；规范研究只用于接口边界，未复制第三方实现。

**遗留风险：** GitHub Pages 线上工作流、HTTPS 下系统分享面板和真实手机剪贴板尚未在当前环境实测。

**实际改动：** 首页改为跨区域精选 24 城，完整 222 城继续保留在三个目的地目录和全站搜索索引；轮播首屏只输出第一张图片的 `src`，运行时仅预取当前与下一张。新增暂停控件、系统减少动态检测、非活动链接移出 Tab 顺序，并为浏览器审计加入节点、图片和资源指标。

**验证结果：** 两项新契约先红后绿；首页由 803,870 字节降到 281,122 字节，约减少 65%，目录页仍有 222 张独立城市卡。四视口 16 个组合全部 200 且无控制台、请求、HTTP 或横向溢出错误；1366/390 首页节点均约 4440，14 张轮播中初始只水合 2 张。第一次浏览器回归因受控本地服务已退出而如实出现 `ERR_CONNECTION_REFUSED`，重启服务后连续两次矩阵通过；桌面和手机首屏截图已人工复核。

**遗留风险：** 首页仍承载较长的综合攻略正文，手机总滚动高度约 3.36 万像素；下一轮需优先调整手机首屏的信息顺序，而不是继续用隐藏节点压缩内容。

## 2026-08-24 升级第 38 轮：手机决策层级与标准键盘标签页

**问题：** 390px 首页和城市页的三块长摘要把实景图推到首屏之外；用户中心 9 个入口在 360/390px 被铺成五行按钮；底部快捷栏未考虑刘海屏安全区且触控目标仅 36px。

**修改文件：** `tools/build_travel_html.py`、`tools/test_product_contract.py`、`tools/browser_audit.py`、生成的 `user.html`、首页、城市页、`assets/travel.css` 与 `assets/travel.js`。

**遗留风险：** 横滑内容依赖部分露出来提示继续滑动；未来若增加更多关键入口，应优先合并信息架构，而不是继续增加标签数量。

**修改文件：** `tools/build_travel_html.py`、`tools/roadtrip-app.js`、`tools/roadtrip.css`、`tools/browser_audit.py`、`tools/test_product_contract.py`、`tools/test_roadtrip_build.py`、`tools/test_city_expansion.py`、`tools/test_priority_city_images.py` 与全站生成页面/公共资源。

## 2026-08-24 升级第 40 轮：按需搜索、真实离线回退与性能预算

**问题：** 约 390KB 的全站搜索索引在每个页面首屏同步加载，并被 Service Worker 首次安装预缓存；未访问页面断网时，导航逻辑会用首页作为兜底，地址与内容不一致，用户难以判断页面到底是否缓存。项目也没有能阻止首页、公共脚本和样式重新膨胀的自动预算。

**原因：** 搜索索引与应用壳被当成同一优先级资源；离线策略只追求“总有页面可显示”，没有区分精确命中缓存与未缓存路线；性能改进只有一次性测量，没有长期契约。

**修改文件：** `frontend/src/site-search.ts`、`tools/build_travel_html.py`、`tools/browser_audit.py`、`tools/offline_audit.py`、`tools/test_product_contract.py`、`tools/test_pwa_cache.py`、`tools/test_performance_budget.py`、生成的 `README.md`、`sw.js`、页面和 Vite 资源。

**实际改动：** 页面只在 `body` 记录带构建版本的搜索索引地址，用户输入搜索词后才异步载入；加载中、加载失败、离线已缓存三种状态都有明确反馈，索引不再进入首次安装 App Shell。导航保持网络优先，已访问页面精确回退到自身缓存，未访问页面改为带“返回已缓存首页/重新尝试”的专用 503 离线页，不再用首页冒充目标城市。新增自持临时 HTTP 服务的真实断网审计，避免只切换 `navigator.onLine` 造成 Service Worker 假通过；新增首页 HTML、卡片数、轮播水合、公共 CSS/JS 和按页数据隔离预算。

**验证结果：** 3 项新增搜索/PWA 契约先红后绿，性能预算同步通过。自持服务器实际关闭后，已访问青岛页离线仍返回 200、标题和正文保持、离线提示可见；按需搜索索引离线从缓存恢复 1 条澳门结果；未缓存的澳门唯一查询路线返回 503 专用说明。最终 `npm run check` 通过 13 项 Node 与 132 项 Python 测试，站点验证为 0 缺链、0 缺锚点、0 重复 ID、0 空文件和 0 缺失图片替代文本；`npm run stage` 产出 229 个 HTML，未夹带地图配置。最终四视口 16 个浏览器组合全部 200，错误、溢出、坏图、无名称控件、空链接和无尺寸图片均为 0；所有首屏在交互前均未请求搜索索引，首页初始资源解码量约 357KB，搜索后仍返回 7 条青岛结果。

**遗留风险：** 首次离线且从未执行搜索时无法使用完整索引，这是减少首次安装成本的明确取舍；搜索一次后可由运行时缓存继续使用。Service Worker 与 GitHub Pages 的真实线上缓存升级仍必须在提交、推送和公开部署完成后另行核验。
